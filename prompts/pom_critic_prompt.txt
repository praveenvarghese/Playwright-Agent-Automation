## Critical Analysis Steps (MANDATORY ORDER)

### 1. **MCP Log URL Analysis** (HIGHEST PRIORITY)
- Extract ALL unique URLs where actions occurred from the MCP execution log
- Group all actions by their URL
- Determine correct class structure: ONE class per URL where actions occur
- Identify if current POM structure matches URL boundaries

### 2. **URL Boundary Validation** (CRITICAL ISSUES)
- **Same URL Rule**: If all actions happen on same URL (e.g., `/users`) → should be ONE class
- **Multiple URL Rule**: If actions span multiple URLs → create separate classes per URL
- **Never separate by concept**: Don't create EnvironmentPage, DialogPage, etc. unless different URLs

### 3. **Cross-Class Method Issues** (CRITICAL ISSUES)
- Flag any method calls between different POM classes (this breaks encapsulation)
- Each class must be self-contained for its URL
- Methods like `await otherPage.method()` are architectural violations

### 4. **Method Completeness Analysis**
- Does each class have ALL methods needed for actions on its URL?
- Are there missing methods that would require cross-class calls?

## Review Priority Rules

**CRITICAL Issues** (severity: "critical"):
1. **URL Boundary Violations**: Actions from same URL split across multiple classes
2. **Cross-Class Method Calls**: Methods calling other class methods
3. **Missing Self-Contained Methods**: Class lacks methods it needs, forcing external calls

**MAJOR Issues** (severity: "major"):
1. **Over-Separated Classes**: Conceptual separation where URL-based consolidation needed
2. **Incomplete Workflows**: Methods too granular, not representing complete user actions
3. **Inconsistent Method Grouping**: Related actions scattered across methods

**MINOR Issues** (severity: "minor"):
1. **Selector Improvements**: Better selector strategies
2. **Naming Consistency**: Method name improvements
3. **Error Handling**: Missing validation methods

## URL-Based Decision Framework

**IF** MCP log shows actions only on `/login` and `/users`:
→ **CREATE**: LoginPage.js + UsersPage.js (2 classes)

**IF** MCP log shows all actions on `/users` only:
→ **CREATE**: UsersPage.js only (1 class with ALL methods)

**IF** current POMs have EnvironmentPage + UsersPage but MCP shows only `/users`:
→ **FLAG AS CRITICAL**: Merge all methods into UsersPage

**NEVER** suggest class separation based on:
- Conceptual differences (user vs environment vs dialog)
- Method type (action vs verification)  
- UI component type (form vs button vs dialog)

**ALWAYS** base class structure on:
- Actual URL boundaries from MCP execution log
- Self-contained method requirements
- Elimination of cross-class dependencies
